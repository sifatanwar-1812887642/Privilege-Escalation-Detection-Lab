# Unauthorized Sudo / Privilege Escalation Detection Lab

**Prepared by: Sifat Anwar**

## Overview

This project demonstrates how an unauthorized `sudo` privilege escalation attempt on an Ubuntu endpoint can be detected using **Wazuh SIEM**.

A low-privileged test account named `poc_user` attempts to obtain a root shell with `sudo su`. The account is not authorized in the sudoers configuration, Linux records the activity in the authentication log, and Wazuh generates **Rule ID 5405 – Unauthorized user attempted to use sudo**.

The activity is mapped to **MITRE ATT&CK T1548.003 – Sudo and Sudo Caching**.

# 1. Wazuh Manager Installation

On the Ubuntu Wazuh Manager (`10.0.2.6`), update the system and download the official installation assistant:

```bash
sudo apt update && sudo apt upgrade -y
curl -sO https://packages.wazuh.com/4.15/wazuh-install.sh
```

Run the all-in-one installer:

```bash
sudo bash ./wazuh-install.sh -a
```

Verify that the manager is running:

```bash
sudo systemctl status wazuh-manager
```

The dashboard was accessed from:

```text
https://10.0.2.6
```

---

# 2. Install the Wazuh Agent on Ubuntu Target

## Step 1 – Add the Wazuh GPG Key

```bash
curl -s https://packages.wazuh.com/key/GPG-KEY-WAZUH | sudo apt-key add -
```

Observed result:

```text
OK
```

## Step 2 – Add the Wazuh Repository

```bash
echo "deb https://packages.wazuh.com/4.x/apt/ stable main" | sudo tee /etc/apt/sources.list.d/wazuh.list
```

## Step 3 – Update Package List

```bash
sudo apt update
```

## Step 4 – Install Wazuh Agent

```bash
sudo apt install wazuh-agent -y
```

Observed package version in the completed lab:

```text
wazuh-agent 4.14.7-1
```

Wazuh agent location:

```text
/var/ossec/
```

---

# 3. Configure the Wazuh Agent

Edit:

```bash
sudo nano /var/ossec/etc/ossec.conf
```

Configure the manager address:

```xml
<client>
  <server>
    <address>10.0.2.6</address>
  </server>
</client>
```

This configures the Ubuntu target (`10.0.2.7`) to communicate with the Wazuh Manager at `10.0.2.6`.

---

# 4. Add the Ubuntu Agent to the Wazuh Manager

On the Wazuh Manager:

```bash
sudo /var/ossec/bin/manage_agents
```

Select:

```text
A) Add agent
```

Agent configuration used in the lab:

```text
Name: ubuntu-target-10.0.2.7
IP:   10.0.2.7
ID:   003
```

Extract the agent key using:

```text
E) Extract key
```

Then on `10.0.2.7` run:

```bash
sudo /var/ossec/bin/manage_agents
```

Select:

```text
I) Import key
```

Paste the key generated by the manager and confirm the import.

# 6. Monitor Linux Authentication Logs

In `/var/ossec/etc/ossec.conf`, the authentication log was added as a monitored log source:

```xml
<localfile>
  <log_format>syslog</log_format>
  <location>/var/log/auth.log</location>
</localfile>
```

# 7. Attack Simulation

> This simulation was performed only in a controlled lab environment.

## Step 1 – Create the POC Account

On the Ubuntu target:

```bash
sudo adduser poc_user
id poc_user
```

Observed identity:

```text
uid=1002(poc_user) gid=1002(poc_user)
```

## Step 2 – Log in as the Low-Privileged Account

```bash
su - poc_user
```

Verify:

```bash
whoami
```

Expected result:

```text
poc_user
```

## Step 3 – Unauthorized Sudo Attempt

From the `poc_user` session:

```bash
sudo su
```

Observed result:

```text
poc_user is not in the sudoers file.
```

This is the unauthorized privilege escalation attempt used for the detection test.

---

# 8. Verify the Linux Authentication Log

From another terminal using the authorized `sifat` account:

```bash
sudo tail -f /var/log/auth.log
```

The authentication log recorded the unauthorized sudo attempt, including:

```text
poc_user : user NOT in sudoers ; TTY=pts/1 ; PWD=/home/poc_user ; USER=root ; COMMAND=/usr/bin/su
```

---

# 11. Containment Response – Lock the POC Account

After confirming the alert, the test account was locked:

```bash
sudo usermod -L poc_user
```

Verify the account state:

```bash
sudo passwd -S poc_user
```

Observed status:

```text
poc_user L ...
```

Where:

```text
L = Locked
P = Password active
```

A login test after containment resulted in authentication failure.

---

# 12. Optional Lab Reset

Because `poc_user` is a test/POC account, it can be unlocked for another authorized lab run:

```bash
sudo usermod -U poc_user
```

or:

```bash
sudo passwd -u poc_user
```

Verify:

```bash
sudo passwd -S poc_user
```

Expected state after unlocking:

```text
poc_user P ...
```
